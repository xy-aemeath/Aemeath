## 四、被问到没做的功能，这么答

> "演示版聚焦规则验证，这是工程问题；正式版接学校认证/数据导入就行，**规则层是可以直接用的**。"

| 被问 | 答 |
|---|---|
| 怎么没有登录 | 演示版用身份切换保证流程可看，正式版接学校统一认证 |
| 怎么不能导入名单 | 演示版预置 24 条数据，导入不影响规则验证 |
| 手机上能用吗 | 响应式布局——**当场把窗口缩窄给他们看** |
| 有测试吗 | 25 条规则逐条手动验证过，彩排跑了 5 遍 |
| 数据量大了行吗 | 几百人单机足够；真正的瓶颈是截止瞬间的写并发，已用事务兜住 |

**套路：承认没做 + 说明为什么不做 + 指出规则层已经想清楚。**

## 五、五个必答的问题

**① 一个人被两个导师要，怎么办？**
两个 offer 都给他，但他只能确认一个，另一个自动失效并触发递补。

**② 确认后反悔怎么办？**
学生不能自助反悔，只能找管理员强制改派，且留审计日志。

**③ 截止那一秒两个人抢最后一个名额？**
确认操作在一个事务里做"查状态 + 扣名额"，只有一个能成功，另一个收到"名额已满"。

**④ 三轮都招不满怎么办？**
名额回流学院池，公示里明确写"空缺 N 个"，不允许暗箱补人。

**⑤ 你们三个人怎么分工的？**
规则 / 界面 / 交付三条线，文件所有权分死，每人只改自己的文件。
