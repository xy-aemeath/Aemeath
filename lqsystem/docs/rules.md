# 业务规则（AI 判断对错的依据）

> 写代码前先读这一页。**代码写不出来可以问，规则想错了整段重写。**

## 角色

- **学生**：填报意向、确认或放弃 offer、查看结果
- **导师**：看报名、打分、发 offer、维护递补队列
- **管理员**：控轮次、看名额、结算本轮、重置演示数据
- **公示页**：只读，不需要登录

## 流程

每一轮都是：学生填意向 → 导师面试打分 → 导师发 offer → 学生确认 → 未录用者进下一轮。
三轮结束后，剩下的进统筹调剂：内部调剂 → 跨室调剂 → 约谈兜底。

**最终必须人人有位置**：所有流程走完，每个学生都必须有一条 `confirmed` 的 offer。
系统里不允许存在"最终未录取"的学生。

## 规则

| 编号 | 规则 |
|---|---|
| R1 | 一个学生一轮最多报 **3 个**导师意向，**不分先后** |
| R2 | 同一轮，同一学生不能对同一导师报两次 |
| R3 | 只有 `rounds.status = 'open'` 的那一轮能填报；关了就只读 |
| R4 | 学生可以在截止前修改自己的意向（整体覆盖，不是追加） |
| R5 | 导师可以给多个学生发 offer，但该导师 **有效 offer 数不得超过名额** |
| R6 | 导师发 offer 时，该学生必须在本轮报过这位导师 |
| R7 | 一个学生可以**同时持有多个** offer（来自不同导师） |
| R8 | 学生手里只有 **1 个** pending offer → **自动确认**，不需要学生操作 |
| R9 | 学生手里有 **2 个及以上** pending → 只能选 1 个；选定后其余 pending 自动变 `declined` |
| R10 | 学生可以"放弃全部"，全部 pending 变 `declined` |
| R11 | 确认 / 放弃前必须先查状态，**不是 `pending` 就拒绝**，不许改 |
| R12 | "查状态 + 改状态 + 改其他 offer" 三步必须在**同一个事务**里 |
| R13 | offer 变成 `declined` 或 `expired` → 自动给该导师递补队列第 1 位发新 offer |
| R14 | 递补队列空了就什么也不做，**不要报错** |
| R15 | 管理员点"结算本轮"：本轮所有 pending → `expired`；本轮 `closed`；下一轮 `open` |
| R16 | 已是最后一轮时点结算 → 提示"已是最后一轮"，不要崩溃 |
| R17 | 已 `confirmed` 的学生，后续轮次不能再填报（接口拒绝 + 页面过滤） |
| R18 | 名额 = 导师 `quota`（固定）；`pending` + `confirmed` 的 offer 都占名额 |
| R19 | 名额为 0 时，"发 offer"按钮必须禁用 |
| R20 | **剩余名额 = quota − 占用**，是算出来的。每轮结束时学院"公布剩余名额"（第 6 步），就是把这个数亮出来 |
| R21 | 三轮内补录；三轮外统筹调剂，顺序：**本室内部调剂 → 全院跨室调剂 → 约谈兜底**，前一级没消耗完不许跳 |
| R22 | **全员安置是硬指标**：流程走完，未安置学生数必须为 **0**，系统不接受"还有人没地方去" |
| R23 | 第三级约谈兜底：管理员可直接指定导师并分配，学生不得再拒绝 |
| R24 | 公示页：`total = confirmed + vacant`，且**未安置人数必须为 0**，否则标红 |
| R25 | **内部调剂候选** = 本轮在**本实训室**面试过、但没有 `confirmed` 的学生（查询推导，不必新建表） |

## 绝对不许做的事

- 不许"先查名额再扣名额"（并发时会超录，必须在一个事务里）
- 不许在接口里信任前端传来的状态（状态一律后端查）
- 不许用中文当状态值
- 不许返回裸数组（必须 `{"ok":..,"data":..}`）
