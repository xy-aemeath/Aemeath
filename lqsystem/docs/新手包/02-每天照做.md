# 每天照做（10 分钟看懂，之后每天重复）

---

## 开工 3 步

**1. 拉最新**

```
cd D:\lqsystem
git pull
```

**2. 清掉别人的文件**（上次 AI 可能顺手改过）

```
git checkout -- app.py db.py
```

（换成"不属于你"的那些文件）

**3. 打开角色卡，看今天做哪个 T**

`docs/roles/几号.md`。一次只做一个，T1 没完不跳 T2。

---

## 发口令：永远是这四句

```
先读 CLAUDE.md、docs/contracts.md、docs/rules.md、docs/roles/2.md。
只做 T3，只改 routes_mentor.py 和 static/my-offers.html。
先告诉我你打算怎么做，不要写代码。

（它说完方案，你确认后）
可以，按这个写。
```

四句各防一件事：

| 句子 | 防什么 |
|---|---|
| 先读那四个文件 | AI 不知道规则、自己编字段名 |
| 只做 T3 | 它一口气写一堆，你验不过来 |
| 只改这两个文件 | 它碰别人的文件，害全组 |
| 先告诉我怎么做 | **最值钱的一句，省一半返工** |

方案里只看三处：**改的文件对不对、字段名对不对、有没有偷偷加功能**。

---

## 做完：亲手点 3 遍

**这一遍不能省，也不能让别人替。**

| 第几遍 | 怎么点 |
|---|---|
| 正常 | 走一遍主流程，看结果对不对 |
| 边界 | 该限 3 个的选第 4 个；名额用光再点发放；对已确认的再点确认 |
| **连点 5 次** | 快速连点"提交""确认"，刷新看数据库是 1 条还是 5 条 |

还有一条铁律：**页面上的数字不算数，刷新之后的才算法（Ctrl+F5）。**

---

## 收工 4 步

```
git status                                    ← 只应看到自己的文件
git add routes_mentor.py static/mentor.html   ← 写具体文件名，不要写 .
git commit -m "2号：导师页打分保存"
git push
```

看到别人的文件就先 `git checkout -- 文件名` 还原。

---

## 群里发三句（3 分钟）

```
2号：昨天完成 导师页打分；今天做 offer 确认页；卡在 不知道事务怎么写
```

**"卡在"那句最重要。卡住超过 2 小时必须说。** 你憋一天，可能只是别人 10 分钟的事。

---

## AI 越界了，一行命令还原

```
git checkout -- 文件名
```

然后告诉它：`以后只改我指定的文件，现在把 X 的改动还原。`

---

## 报 bug 的正确说法

别说"不对"。说这三句：

```
我期望：连点 5 次确认，数据库只有 1 条 confirmed。
实际：出现了 5 条。
以下是代码：<粘贴>
请只改 routes_mentor.py 修这个问题。
```
