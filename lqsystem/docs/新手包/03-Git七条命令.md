# Git 七条命令（15 分钟）

---

## 第一次：拉仓库（只做一次）

```
cd /d D:
git clone <组长给你的地址> lqsystem
cd lqsystem
```

路径必须纯英文。中文路径会引发一堆莫名其妙的错。

---

## 七条命令，够你用整个项目

| 什么时候 | 命令 |
|---|---|
| 早上开工 | `git pull` |
| 提交前 | `git status` |
| 提交前 | `git add 具体文件名` |
| 提交时 | `git commit -m "说明"` |
| 收工 | `git push` |
| 改坏了 | `git checkout -- 文件名` |
| 误提交了 data.db | `git rm --cached data.db` |

**完整的一天：**

```
git pull
（干活）
git status
git add routes_mentor.py static/mentor.html
git commit -m "2号：导师页打分保存"
git push
```

## `.gitignore`：为什么 `data.db` 绝对不能提交

`.gitignore` 是一个文件，里面写的名字，Git **永远不管**。我们仓库里已经有了：

```
data.db
__pycache__/
.venv/
*.log
```

`data.db` 是**每个人本地自己生成的数据库**。如果提交上去：

| 发生什么 | 后果 |
|---|---|
| 1 号 推了 | 2 号 一 pull，本地数据被覆盖成 1 号的 |
| 2 号 也推 | 1 号 的又被覆盖回来 |
| 每次 pull | 报冲突，而且 `.db` 是二进制，**Git 没法合并，只能二选一** |

**数据来回打架，无解。** 所以每人本地一份，靠 `seed()` 自动填假数据。

**已经误提交了怎么救：**

```
git rm --cached data.db
git commit -m "把 data.db 移出版本控制"
git push
```

`--cached` 不能漏，否则本地数据库会被真删掉。

## 八个字：写具体文件名，别用 `git add .`

`git add .` 会把**所有**改动都提交，包括 AI 顺手改的别人的文件。

写具体文件名，等于给自己上保险：**即使 AI 改了 `app.py`，也传不上去。**

---

## 冲突了（常见，不用怕）

**现象**：`git pull` 之后满屏 `CONFLICT`。

**处理**：

1. 看是哪个文件
2. **是你自己的** → 群里说"X 文件我在处理，大家先别动"
3. **是别人的** → 群里说，让主人处理
4. **实在搞不定**：

```
git checkout -- 冲突的文件名
git pull
```

= 扔掉自己对这个文件的改动，用服务器版本。**认了，重做这点活比重写便宜。**

> 冲突的唯一根因是"两个人改了同一个文件"。这就是文件所有权表存在的理由。

---

## 四个千万别

1. 别 `git add .`
2. 别提交 `data.db`
3. 别在冲突时"两边代码都留着"——必然语法错误
4. 别在答辩前一天改代码
