# 口令怎么写（不是契约）

> 这份讲的是**怎么把话写给 AI**：格式、禁止项、报错怎么说。
> **不负责"技术栈/字段名/class 名"这些规定**——那些在 `docs/contracts.md` 和 `docs/开工确认单.md` 里。
>
> 不管谁、做哪个 T，口令都长这样。**照抄，只改"做哪个 T"和"改哪些文件"。**

---

## 一、口令的四段（缺一段就容易翻车）

```
① 先读：CLAUDE.md、docs/contracts.md、docs/rules.md、docs/roles/N.md
② 我是 N 号。只做 TN。只改 X、Y 两个文件，其他文件一律不许动。
③ 【完成定义】具体到能跑的命令 + 期望输出
④ 【自检】启动服务 → 跑命令 → 贴真实输出 → 不过就自己改 → 列改动文件
```

四段各防一件事：

| 段 | 防什么 |
|---|---|
| ① 先读 | AI 不知道规则，自己编字段名 |
| ② 限范围 | 它一口气写完整个项目，你验不过来 |
| ③ 完成定义 | 它说"已完成"，但其实只写了一半 |
| ④ 自检 | 它不跑就交，把报错留给你 |

---

## 二、必带的三句"禁止"

```
不要执行任何 git 命令。
不要引入任何前端框架、UI 库、ORM。
不要修改我指定的两个文件以外的任何文件。
```

第一句防它替你 `git add .` 然后 `push`；
第二句防它给你装 React；
第三句防它顺手改队友的代码。

---

## 三、它写完，你必须检查的三件事（3 分钟）

1. **改动清单**里是不是只有你点名的文件
2. **curl 的真实输出**是不是真跑出来的（不是它编的）
3. **字段名**是不是 `contracts.md` 里那些（`status` 不是 `state`）

---

## 四、它做错了，用这个格式说（不要只说"不对"）

```
我期望：<具体现象>
实际：<具体现象>
复现步骤：<点了什么>

请只改 <文件名> 修这个问题，不要动其他文件。
修完自己跑一遍验证，把输出贴给我。
```

**例子：**

```
我期望：连点 5 次"确认"，数据库里只有 1 条 confirmed。
实际：出现了 5 条。
复现：打开 /api/_selftest/t4 跑一次，返回 5 个 success。

请只改 routes_mentor.py，在 confirm 前加状态校验并包在事务里。
修完自己跑一遍 /api/_selftest/t4，把输出贴给我。
```

## 五、接口路径规则（避免三个人撞车）

```
/api/{模块}/{动作}
```

| 谁 | 路径前缀 |
|---|---|
| 1 号 | `/api/intentions`、`/api/mentors`、`/api/debug` |
| 2 号 | `/api/mentor/...`、`/api/student/...`、`/api/offers/...` |
| 3 号 | `/api/admin/...`、`/api/public/...` |

**各人的接口只有自己用，不跨人调用。** 三个人之间共享的只有**数据库表**，不是接口。
所以你不需要等别人的接口写完——直接查表。

---

## 六、绝对不要让 AI 做的事

- 不要让它 `git add` / `commit` / `push`
- 不要让它改 `CLAUDE.md`、`docs/` 下的任何文件
- 不要让它"顺便"加导出、加登录、加图表
- 不要让它写单元测试（用临时自检接口代替，见各人口令）
- 报错时不许它"注释掉这段先跑起来"

---

## 七、什么时候可以真的走开

发完口令就可以走，**前提是口令里有第 ③④ 段**。

它得启动服务、跑命令、看输出、改、再跑——这些它自己能做。

**但业务对不对，它证不了。** 所以回来之后你还要点 1 分钟（每个 T 的口令最后都写了"你回来只检查什么"）。
